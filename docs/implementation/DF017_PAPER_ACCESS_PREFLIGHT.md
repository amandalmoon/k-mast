# DF-017 PAPER 접근 사전 점검

현재 판정은 **DF017_COLLECTION_PENDING_APPROVAL**이다. DF-016의 공식 HTTPS 경로 문서는 실제 호출 승인·현재 키의 서비스 권한·보관권 증거가 아니다. 새 KIS 인증·가격 조회·TLS 연결 시험·WebSocket/승인키·계좌·주문·LIVE·예약은 실행하지 않았다.

| 필수 항목 | 현재 상태 | 실행 경계 |
|---|---|---|
| 새로운 인간 승인 원문 | 없음 | 정확한 proposal 해시·동일 범위·PAPER·발급/만료시각·원문 SHA 필요 |
| 서비스 권한·현행 한도 | 미확인 | PAPER 시세 권한과 3.10초보다 엄격한 정책의 검토 근거 필요 |
| 보관·연구·해시 권리 | 미확인 | 원문/연구 30일, 별도 해시 보존 허용의 검토 필요 |
| 10/20 거래일·특별개장·두 종목 상태 | 미확인 | 일자·시장 J·종목 고정, 독립 문서 검토 필요 |
| PC 시계 오차 | NULL | 독립 측정 오차 상한 0.5초 이하를 이 구현의 보수적 조건으로 사용 |
| 공식 HTTPS 경로 | 문서 있음 | 실제 TLS 신뢰 체인·호스트명 검증은 런타임에 별도로 강제 |

`https_bar_gate.TRUSTED_REVIEWS`는 비어 있다. 사용자 파일의 `reviewed=true`나 자가 작성 문서 해시가 승인·서비스 권한의 신뢰 루트가 되지 않는다. 실제 인간 메시지와 독립 근거를 검토한 뒤 승인/사전검증의 canonical SHA 쌍을 등록하는 **후속 검토 변경**이 필요하다. CLI 등록 스위치·환경변수·사용자 registry 파일은 없다. 이는 승인 문서만으로 다른 필수 검사를 통과시키지 않기 위한 경계다. 이번 변경에는 실제 승인 쌍을 넣지 않았다.

검토 등록 뒤에도 파일 SHA·범위·날짜·만료·권리·시계·한도를 재검사하며 실제 전송은 별도 TLS 검증을 거친다. 새 승인 원문은 발급 후 72시간 이내여야 하고 만료는 관측 창 종료를 넘길 수 없다. 필수 증거가 부족하면 키 로더·HTTP 객체·실제 store/lock 생성 전에 차단한다. 현재 보관권·시장상태를 확인했다고 주장하지 않는다.
