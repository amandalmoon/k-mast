# Data-first exploratory result

실제 KIS 가격을 이용한 Alpha A candidate-v1 탐색 재생을 완료했다. 삼성전자 기본 시나리오는 연구자본 10,000,000원에서 비용 후 536,495.75원, MDD 1.82%, 체결 30건이다. 같은 기간 단순 보유 성과보다 낮다. 상태는 **EXPLORATORY_REAL_DATA / ECONOMIC_EDGE_UNVERIFIED**이며 확인적 OOS는 실행하지 않았다.

## 수집과 재현

사용자가 승인한 2025-10-17~2026-10-16, 개별 종목 6개와 지수 2개, 최대 48요청 범위에서 PAPER 인증 설정으로 37요청(인증 2, 시장자료 33, 마스터 2)을 사용했다. 최소 요청 간격은 3초다. 계좌·주문·취소 호출은 모두 0이다. 요청 예산, 제한된 재시도, 날짜 역방향 페이지네이션, 원본 해시, 캐시와 재개를 적용했다.

RAW 일봉 1,464행, 지수 488행, 삼성전자 수정 일봉 244행, 현재가 스냅샷 1행으로 총 2,197행을 확보했다. 종목별 관측일은 244개다. 토요일 조회에서 당일 분봉은 실제 응답 0행이었다. 현재가 누적 스냅샷을 과거 체결로 간주하지 않는다. 현재 마스터는 KOSPI 2,571개·KOSDAQ 1,825개 항목이며 보통주 전용 또는 과거 PIT 유니버스가 아니다. 삼성전자 원/수정 종가 244쌍은 일치했으나 기업행사 부재나 배당 총수익을 증명하지 않는다.

원자료와 관측가격·신호·가상 체결·장부를 포함한 72개 재생 파일은 Git 제외 `data/data-first-private-market-v1/exploration-v2/`에만 보관한다. 공개 증거는 `artifacts/data-first/collection.json`, `exploration-summary.json`, `exploration-contract-v2.json`이다. 6종목 × 3시나리오 × 4모형을 독립 실행했으며 공동계좌 포트폴리오 성과가 아니다.

```powershell
.\.venv\Scripts\python scripts/run_data_first_exploration.py
.\.venv\Scripts\python scripts/check_data_first_evidence.py --private
.\.venv\Scripts\python scripts/verify.py --milestone data-first
```

수집 명령 `scripts/collect_data_first.py --execute`는 인증·조회가 발생하는 별도 명령이다. 위 재생은 저장된 자료를 사용한다.

## 해석과 제한

원 관측의 품질 flag와 취득시각은 보존한다. 별도 탐색 경로는 날짜 전체를 감싸는 기간 경계와 다음 관측 세션의 가용·체결시각을 명시적인 가정으로 사용한다. 이는 관측된 과거 타임스탬프가 아니다. 전일 정보로만 신호·수량·지정가를 만들고 다음 관측일 시가에 불리한 슬리피지를 적용한다. 전일 거래량으로 수량을 제한하고 매도대금은 두 번째 관측 세션 전까지 재사용하지 않는다. 2025-11-13과 2026-01-02는 보수적인 시나리오 체결 제외일이며 인증된 거래 달력으로 주장하지 않는다.

현재 생존 표본, 기업행사·배당·과거 거래정지 미확인, 호가·대기열 부재, 실제 비용 미확인, 관측일 기반 달력이라는 제한이 있다. 과거 종목 마스터나 체결 tick을 생성하지 않는다. 배당·기업행사를 포함한 총수익은 NULL이다. 기존 품질·경제성 게이트와 LIVE 차단을 변경하지 않았다. 탐색 성과를 시장 전체·확인적 OOS PASS로 일반화하지 않는다. Alpha B~D에 필요한 분봉·이벤트 자료가 부족하다는 사실은 A의 검증 가능한 재생을 중단시키지 않는다.

## 공식 구현 비교

[공식 저장소](https://github.com/koreainvestment/open-trading-api)의 커밋 `2077773a69a428daf63e148182511f068cc45de3`을 고정해 9개 파일을 조사했다. 경로·URL·해시는 `artifacts/data-first/upstream-review.json`에 있다.

- `backtester/`: 일봉 종료일 역방향 조회와 Lean CSV 캐시를 참고했다. K-MAST는 Decimal·원본 해시·재개 예산을 유지하고 조용한 중복 제거를 채택하지 않았다.
- `strategy_builder/`: 단일 일봉 호출과 단기 캐시를 비교했다. 잔고 경로를 포함하므로 모듈 전체를 가져오지 않았다.
- `stocks_info/`: 공식 ZIP의 CP949 고정폭 구조를 확인했다. TLS 검증과 정확한 ZIP 멤버 읽기를 사용하며 샘플의 TLS 비활성화·전체 압축해제를 채택하지 않았다.
- `examples_llm/domestic_stock/`, `examples_user/domestic_stock/`: 일봉·지수·당일 분봉 경로와 TR을 확인하고 실제 응답으로 범위를 확인했다. 계좌·주문 기능을 가져오지 않았다.

참조 코드는 비공개 조사 폴더에만 두었고 실행·복사·재배포하지 않았다. 추가 라이선스 문서 반복 대신 범위가 명시된 자체 구현과 결과를 완성했다.

## 검증

기존 296개와 신규 16개를 합한 pytest 312개가 통과했다. Ruff, 포맷, mypy, build, 기존 KM-002/003/004 장부·OMS 재생과 독립 Decimal 회계 검사도 통과했다. 72개 비공개 장부의 현금+보유 평가, 수수료 합계, 신호 인과관계를 재검사했다. 21봉 계산 최적화 전후 18개 경제성 집계는 모두 동일하다. 원본 사양·기존 전략·위험·OMS 계약은 유지한다.

구현 커밋 `20a7e1ceb264555e3cb6a1927a93c3966b175092`의 [GitHub Actions](https://github.com/amandalmoon/k-mast/actions/runs/38989633353)는 Python 3.11·3.12 모두 성공했다. 양쪽 작업 로그에서 각각 312 passed, mypy 64개 소스 통과, sdist/wheel 생성과 독립 회계 검사 PASS를 확인했다. `artifacts/data-first/remote-ci-implementation.json`에 정확한 SHA와 작업·단계 결과를 보관한다.
