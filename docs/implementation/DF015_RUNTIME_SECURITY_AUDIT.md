# DF-015 실행 보안 감사

## 결함과 수정

DF-014의 `authorize()`는 범위·날짜 및 파일 해시 일치를 검사한다. 파일의 `verified=true`나 스스로 만든 파일의 SHA-256은 공급자 보안 진술의 진실성이나 인간 승인의 독립적 증거가 아니다. 기존 테스트의 SYNTHETIC 문서로도 이 하위 검사가 통과함을 재현했다. 이후 `connect_paper()`가 상수 `ws://`로 연결하는 코드는 문서와 실제 보호 상태를 결합하지 못했다.

DF-015의 `paper_security.require_secure_transport()`를 실제 실행 경계에 추가했다. 이 버전에는 공식 검증된 암호화 경로가 없으므로 승인된 경로 목록을 비워 두고 모두 거부한다. 운영상 우회 플래그·환경변수·JSON 등록 기능은 없다. 확인되지 않은 wss URL도 차단한다. TLS를 구현하거나 시험했다고 주장하지 않는다.

| 경계 | 검사 순서와 결과 |
|---|---|
| `scripts/collect_df014.py` | 실행 옵션 검사 뒤 보안 게이트, 그 다음 문서/환경 로딩. 게이트 거부 시 키를 읽지 않음 |
| `PaperCollector.guard()` | 실제 고정 endpoint의 보안 검사 후 기존 범위/해시 검사. `issue`, `collect`, `send`가 공통 사용 |
| `PaperCollector.issue()` | guard가 예약·승인 기록 작성·비밀값 접근·HTTPS 객체 생성보다 먼저 실행 |
| `connect_paper()` 직접 호출 | 외부 라이브러리 connector 생성 전에 동일한 차단 |
| `send()` 직접 호출 | 토큰을 미리 삽입하거나 문서를 위조해도 전송 전에 차단 |

보안 검증 후 실제 주소만 변경하는 경우도 미등록 경로로 거부된다. PAPER→LIVE, 임의 날짜, 만료된 파일럿, stale·위조 문서로도 실행할 수 없다. 에러에는 endpoint·문서·키·계좌·응답 본문을 삽입하지 않는다. 일반 Python 코드 변조나 프로세스 자체의 악성 monkeypatch를 막는 암호학적 실행환경을 구현했다는 뜻은 아니다.

## 테스트 경계와 보존

기존 608개 사례와 모든 기존 결과를 유지했다. 기존 DF-014 네 가지 합성 HTTP/전송 테스트는 새 보안 게이트를 **그 테스트 안에서만 명시적으로 mock**하여 원래 응답·예산·비밀정보 검사를 유지한다. 운영 코드에 합성 허용 모드는 없다. 새 DF-015 테스트는 이 mock 없이 운영 gate가 인증·연결·전송 전에 차단함을 검증한다. 파일 해시만 검사하는 기존 하위 `authorize()`를 보안 승인으로 재해석하지 않는다.

만료 판정은 timezone-aware 시간을 받는다. 2026-10-19 09:25 KST부터 `DF014_MISSED_OBSERVATION_WINDOW`이며 다른 날짜에 자동 실행하지 않는다. 기존 DF-014 보고서는 당시 결과로 보존하며 새 판정은 DF-015에 기록한다. 이 함수의 시간 입력은 실제 시계 정확성의 증명이 아니다.

## 후속 안전 경로 구현 조건

공식 서비스별 정확한 endpoint와 보안 문서를 코드 버전·프로토콜 해시에 고정해야 한다. 서버 이름 검증, 신뢰 체인 검증, 최소 TLS 정책, redirect/proxy 및 마지막 hop 보호를 검토해야 한다. 문서상 적격과 실제 TLS 세션 인증을 분리하고, 승인키 취득 전 경로 적격성을 확인하며 비밀 송신 전 TLS 인증을 끝내야 한다. 임의 사용자 문서의 boolean을 신뢰 루트로 삼지 않는다. 새 인간 승인 원문·정확한 범위·발급/만료시각·재사용 방지와 예산을 결합해야 한다. 이 단계에서는 해당 연결 구현·시험을 하지 않았다.
