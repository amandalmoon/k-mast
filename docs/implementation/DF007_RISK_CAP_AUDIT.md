**RISK_CAP_SEMANTICS_VERIFIED / RISK_REDUCTION_UNVERIFIED**.

수량은 `floor(target * 당시NAV / 한도가격)`와 제출 주문을 대조했다. 실제 체결 수량은
용량 제한의 영향을 받았다. 체결 직후 비중은 체결가격 원가 비중과도 구별하고,
reference가 표시하는 개장가 기준으로 수수료·슬리피지가 반영된 현금과 NAV를 썼다.
매일 `현금 + 수량 * 종가 = NAV`, 매매·수수료·운영비 현금 보존식을 독립 재구성했다.
최초 목표 적합성과 보유 중 평가비중 기준 초과를 다른 검사로 보존했다.

## 승인된 계약의 의미

원본 v1.2 04 문서 2.4는 예산·종목 절대 목표·계좌 위험 비중을 구분한다.
3.4 및 5.2는 LIVE 집중·ES·손실 한도를 **사전 승인 미정/연구용 후보**로 명시한다.
`AlphaConfig.max_weight=.25`는 연구 전략의 목표 상한이다. `ReferencePortfolio`는
독립 회계와 주문·현금 제약을 재생하며, 중앙 계좌의 지속 위험 감시기를 실행하지 않는다.
별도 `MockRiskPolicy.max_symbol_weight`는 기본 None이고 합성 승인 정책과도 별개다.
SignalIntent 스키마는 0~1, snapshot 합계는 1 이하이며, D1의 .25 연구 규칙이 더 좁다.
Reference 자체에 지속 .25 노출 상한을 강제하는 감시 분기는 없다.

따라서 DF006의 .25 대비 초과 관측은 그대로 유지하지만, 이를 이미 승인된 LIVE의
지속 한도 위반이라고 부르는 것은 정확하지 않다. 목표 .25만으로 항상 실제 평가비중
≤.25가 보장된다는 해석도 잘못이다. 이번 감사로 LIVE 수치를 새로 승인하지 않는다.

기존 D1은 최초 진입 또는 만기/손절/정정의 전량 감축 때만 reference.submit을 호출한다.
보유 중 target이 .25로 표시돼도 부분 리밸런싱을 제출하는 분기는 없다. 이것이 가격
상승 후 비중이 즉시 줄지 않은 이유다. 원본 신호·제출 조건·원장·손익은 수정하지 않았다.

STRESS도 최초 체결 632주, 직후 23.1156%, 최대 26.3981%, 기준 초과 2일이다.
PARTIAL은 최초 체결 325주, 최대 13.8543%지만 만기 감축 후 41주가 남았다.
위험감축 미이행 3일을 HOLD로 보존했다. 낮은 평가비중을 청산 성공으로 해석하지 않는다.

## 별도 후속 연구 명세

동결 D1의 수익을 다시 쓰지 않고 새 버전에서만 다음을 사전 등록할 수 있다.

1. 완료된 종가에서 연구 기준 초과를 관측하고 다음 적격 판단 때 감축 의도를 만든다.
2. 그때 사용 가능한 NAV·실제 정수 보유량·유효 가격으로 목표 수량을 계산한다.
   목표 수량 계산 가격과 매도 한도가격을 혼동해 reference 변환 수량이 달라지지 않도록 대조한다.
3. 제출·거절·실제 모델 체결·만료·잔량을 별도 상태로 기록한다. 한도·용량·정지·갭을
   무시한 다음 시가 전량 체결은 허용하지 않는다.
4. 부분체결이나 최소 1주 잔량이 남으면 HOLD다. 미확인 체결을 NAV에서 제거하지 않는다.

이 정책의 경제성 곡선은 이번에 만들지 않았다. 종가 후 감축 요청은 장중 또는
overnight 연속 비중 보장을 뜻하지 않는다. 실제 호가·체결·거래정지 자료와 승인된
계좌 위험 정책, 중앙 OMS 실행·잔고 대사가 필요하다. 실전 위험감축은 미검증이다.
실제 설계에서는 여러 전략·수동 보유·미체결 매수의 잠재 수량까지 계좌에 합산하고,
승인된 한도 초과 시 신규 위험 증가를 차단해야 한다. 미체결 매도를 이미 감축한 것으로
빼지 않으며, 유효 호가·세션·정지 상태를 확인한 중앙 OMS의 감축과 확인 체결·잔고를
대사해야 한다. 이 설계 설명은 이번 단계의 LIVE 또는 주문 권한 승인이 아니다.
